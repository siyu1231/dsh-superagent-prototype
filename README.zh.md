# dsh-superagent

> **仅供研究参考的原型，不是 DeepSeek 的正式产品。** 这份代码来自团队日常开发中的实践，其中大量工程工作由编码智能体完成。请把它当作研究代码，而不是可上生产的软件：它可能仍有缺陷，编码风格与工程实践也可能不一致。在你自己的环境里使用前，请先审阅并调整。
>
> 为了公开，我们做过一些调整，因此它与我们的内部版本、以及《Exploring Super-agent Design: Towards a More Autonomous Agent System》一文描述的实现在细节上并不完全一致。文中讨论的部分设计属于后续方向，本原型并未实现。

dsh-superagent 是一个主动型编码智能体，服务于**你交给它的工作目录**，以 [DeepSeek Harness](https://www.deepseek.com/en/harness/) 插件包（bundle）的形式提供。每个工作目录都是 DSH 工作区列表里的一个工作区，可以在它上面绑定一个 GitHub 仓库。智能体会监听所有已绑定仓库，以及（可选的）飞书。当名单内的某个人请求它做事时，它会开一张工单，在**该工作区旁边属于自己的目录**里干活，然后回到原对话里答复——通常是一个 PR。网页面板负责告诉你哪些事情需要人来处理，并标出每张工单在哪个工作目录里跑。

它同时也是一种与智能体协作的方式：**尽量少占用人的注意力，尽量多交付价值。** 一个能为整个团队行动的智能体，也可能浪费整个团队的注意力，所以它只在被请求、或团队写下的规则允许时行动，并且只在需要人动手或结果可以派上用场时才说话。[docs/000-philosophy.md](docs/000-philosophy.md) 解释了这条原则，以及它对运维者提出的要求。

## 安装

安装步骤较多，所以由智能体陪你一起做。对你的编码智能体说：

> 阅读本仓库的 SETUP.md，和我一起把 dsh-superagent 装好。

它会一次只问一个简短的问题，先把完整计划给你看一遍，然后安装并配置好一切。[SETUP.md](SETUP.md) 是它遵循的步骤。

## 工作目录

工作目录决定了"活在哪里干"和"工单从哪个仓库来"。设置页的 **执行 → 工作目录** 会列出它们：每一项有名称、目录、可选的仓库、可选的准备命令，以及启用开关。目录留空表示使用执行根目录；一个仓库只能绑定到一个工作目录。

这份列表不是"另一份文件夹清单"。DSH 本身会为每个会话所在的目录保留一个工作区，面板会把这些目录列出来供你绑定；你在这里绑定的目录也会注册进 DSH 的工作区列表，因此它会和日常工作的文件夹一起出现在左侧。工单自己的目录只在工单进行期间出现在那里，工单结束时条目会被摘掉——目录和会话日志都会保留。

已有的安装会原地升级：GitHub 来源里配的仓库会自动变成第一个工作目录，名称取仓库名。

## 平台支持

同一份代码同时支持 POSIX 系统和 Windows。在 Windows 上，运行时通过 `PATH` 与 `PATHEXT` 解析 `gh` 和 `lark-cli`，写出 `<name>.cmd` 形式的命令包装，并且因为 Node 无法直接启动批处理文件而改用 `cmd.exe` 启动它们；准备命令改在 `pwsh`（或 `powershell.exe`）里执行，而不是 `sh`。在 POSIX 上则保持无扩展名的包装与 `sh -c`。测试套件两边都会跑。
